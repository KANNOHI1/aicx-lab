模試①②③の問題選抜は **3セット分（125問）を一括で解いてから切り出す**。手順は `tools/mockplan.js`（最小費用流）に保存済みで、QB が変わらなければ同じ ID 列を再現できる。

**Why**: 各セットは**章別と型別の2つの配分を同時に**満たす必要がある（①②は章 8/6/10/8/8/10・型 12/8/8/7/7/4/4、③はその半分で端数は型4へ）。mock プールの型分布はこのブループリントと形が違う（特に型1が薄い）ため、①を先に最適化すると希少セルを取り切ってしまい、②が lesson 再利用16問となって上限15を超えた。mock を各セットへ比例配分し、取り分を超える分だけ高コストで許容する形にしたところ ①15/②10/③6 に収まり、**新規作問ゼロ・3セット間の重複ゼロ**で組めた。

**How to apply**:
- 問題を足す・型や章を振り直す・ブループリントを変えるときは `node tools/mockplan.js` を回し直し、出力の ID 列を `MOCKSETS` に貼る。**手で1問ずつ差し替えない**（片方の配分を直すともう片方が崩れる）
- 公開済みの問題 ID は不変（SRS 履歴が紐づく）。ID を変えずに中身を直す分には割付は動かない
- スクリプトは「新規作問=0」を確認する。0でなければプールが足りていないので、埋めるべきセル（章×型）が出力に出る

**2026-08-30 更新（Build F9）— 同居制約とアルゴリズムの分解**

F シリーズで QB 230問中209問を差し替えたため再組成した。あわせて回跨ぎレビューの「同じセットに似た問題が並ぶ」を一般則にした。

- **制約**: ①同じ Section かつ同じ型を1セットに2問入れない ②同じ Section は1セット2問まで ③名指しされた近接4組を同居させない
- **鍵は分解**: ①は「**同じ (章,型) の中でしか起きない**」（型が違えば重複扱いしない）。よって流量で章×型の配分を決めたあと **(章,型) 単位で Section を割り付ける**。**pool（mock / both）を分けて解くと片方が先に Section を押さえて詰む**ので、mock と both はまとめて1つの問題として解く
- **失敗の記録**: 最初は貪欲＋局所探索（未使用問題との交換・セット間交換・横移動）で作ったが、違反スコアが **144→32 で頭打ち**になった。探索を強化しても動かず、上の分解に切り替えたら**探索なしで最適解に到達**したので局所探索は丸ごと削除した。→ [[feedback_decompose_before_search]]
- **解けない残りは隠さず判定して出す**: **Gale-Ryser 条件**（上位 k セットの必要数の合計 ≤ Σ_x min(min(在庫,セット数), k)）でセルごとに可否を判定し、無理なセルと理由を毎回出力する。2026-08-30 時点の残り3セル＝ch2型1（Sec9・Sec11 が各1問）／ch3型4（Sec13 が1問）／ch4型5（Sec22 が1問）。いずれも作問を足す以外に手がない

**検証で見た品質指標**（3セットとも合格）: 正解肢の強い長さ手がかり0件・型3の順位語欠落なし・同Sec同型は 10組→4組（残りは解決不能と判定済み）・3セット間の重複ゼロ・mockplan 再実行で同一 ID 列（決定的）。
