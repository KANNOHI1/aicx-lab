2026-08-31 に web 調査で確定。それまで DESIGN §7 で「50問/100点/8割は代理指標」としていたが、**出題数と時間は実測値と一致していた**。

| 項目 | 内容 | 確度 |
|---|---|---|
| 出題数 | **全50問** | 実受験者の記事と対策サイトで一致 |
| 試験時間 | **75分**。「時間にほとんど余裕がない」 | 複数ソース一致 |
| 満点 | 100点 | 1ソース |
| 合格ライン | **非公開**（AICX協会は公表していない） | 受験者が SNS 観察で「70点以上で合格が複数」と推測 |
| 第1回合格率 | **39.8%**（1,137名受験 / 452名合格） | 実受験者の記事 |
| 出題形式 | 4択の多肢選択式 | 複数ソース一致 |
| 問題の質 | **「1問が長いケース問題」。基礎問題とケース問題が全体の約8割** | 実受験者の記事 |
| 受験環境 | 自宅IBT。不正防止が厳格で、タブ・ウィンドウ切替やページ離脱の履歴を監視。ブックマーク操作でもアラート | 実受験者の記事 |
| 受験料 | 14,800円（税込） | 対策サイト |

**HK が受験者から直接聞いた話（2026-08-31）**: 「基本的に全部が長文読解。50問75分で時間が足りない理由は、その読解に時間を要するから」。web の記述と整合する。

## 公式で確定（2026-08-31・監督がブラウザで一次確認）

出典は [受験要件と動作環境](https://aicx.jp/certifications/strategist/requirements)（aicx.jp は SPA のため fetch では本文が取れない。**ブラウザで開いて読むこと**）。

| 項目 | 公式の記述 |
|---|---|
| 受験期限の意味 | 「試験期間の**最終日の23時59分までに、本試験の受験開始ボタンを押下する必要があります**」「23時59分を経過した後は、本試験を開始できません」＝**開始の期限**。押した後の75分は日をまたいでよい |
| 制限時間の進行 | 「ブラウザを閉じた場合、PCを再起動した場合、再ログインした場合、受験開始ボタンを再度押下した場合であっても、**制限時間は進行します**」。任意の一時停止は不可 |
| 復帰の回数 | 「受験開始ボタンの押下は、最初の受験開始を含めて**合計3回まで**」 |
| 合格ライン | 「**合格ラインは開示しません**」「採点方法、合格基準の詳細、正解、設問ごとの得点、評価ロジック…は開示しません」＝非公開は公式の明言。異議申立ても受け付けない |
| 受験環境 | PC限定（スマホ・タブレット不可）。推奨は Windows 11以降 / macOS Big Sur 11以降、Chrome または Edge の最新版。**Safari・Firefox は対象外**。スリープで中断されうる |
| 監視 | ページ離脱履歴・タブ/ウィンドウ切替履歴は「WisdomBase で当該設定が有効化されている場合に記録される」 |
| 結果通知 | 受験期間終了月の**翌月25日まで**（第2回は 2026-11-25 予定） |
| 再受験 | 1申込につき1回のみ。キャンセル・返金・振替・期間延長は原則不可 |

出題構成は AICX 協会のプレスリリースで「全50問＝**基礎問題／ケース問題／発展問題／時事問題**」「基礎問題とケース問題が全体の**約8割**」。**「約8割」は基礎とケースの合算**であって、ケース単独の割合ではない（受験記 note.com/kazu_t の原文を監督が直接確認）。対策サイトが「ケース問題だけで約8割」と書いているのは**この合算の誤読**の可能性が高い。

## ケースの構造：公式は非開示（2026-08-31 調査で決着）

**1ケースに設問がいくつ付くかは、公式が一切開示していない。** 公式サイト本体・受験要件・FAQ・シラバス配布ページのいずれにも記載なし。受験記4本（kazu_t / sion_neko / あんちゅー / KENJIRO）も**誰も設問数に触れていない**。「1ケース1,200〜1,500字に設問5問」は第三者の予想問題の構造で、そのサイト自身が「本記事の5問構成は独自の設計であり、公式の出題ボリュームを示すものではない」と明記している。

つまり**受験者に聞いても公式の答えは出てこない**。設計側で決める問題になった。

**決着（2026-08-31・公式テキストの実測）**: **共有ケース型は作らない。1問完結の長文問題で作る。**

根拠は手元の公式テキストそのもの。冒頭 L155・L161 に「各Sectionは、知識 → 業務シナリオ → 理解度チェックの流れ」「理解度チェックでは、知識と判断のポイントを**試験形式で**確認します」とあり、**公式が試験形式だと明言している問題が60問ある**（31 Section × 2〜3問）。この60問を機械計測した結果:

| 指標 | 公式テキストの理解度チェック60問 | サイトの QB 246問 |
|---|---|---|
| 問文（ケース本文込み）中央値 | **391字** | 53字 |
| 最大 | 542字 | 276字（最長のケース問題） |
| 300字以上 | **50問 / 60問（83%）** | **0問 / 246問** |
| 共有ケース（1本文に複数問） | **0件**（全問が自己完結） | — |

**共有ケースは公式に1件も存在しない。** 問文が150字未満の問は60問中2問だけで、その2問も前の問のシナリオを参照していない（独立した知識問題）。つまり公式の出題単位は「**1問＝1シナリオ＋1設問**」。

したがって前に書いた「1ケース複数問で実装すれば n=1 も包含できるので安全」という案は**撤回する**。包含関係の理屈自体は正しいが、根拠にしていた「1ケース5問」は第三者サイトが**自ら「独自の設計であり公式の出題ボリュームを示すものではない」と明記している**もので、公式一次資料が手元にある以上そちらに従う。データ構造も画面も変えずに済む。

**作るべきもの**: 既存の短い設問を、公式水準（**300〜550字・中央値390字前後**）の1問完結型へ長文化する。サイトには300字以上の問題が1問もないのが最大のギャップ。

### 予想問題の構造（第三者・参考）

無料公開の予想問題（[中堅都市ガス会社ケース](https://ai-agent-master.com/mock-exam-utility-1/)）は **1ケース1,200〜1,500字に設問5問がぶら下がる**構造。ケース本文には企業概要・問い合わせ5分類の件数比率・As-Is 8ステップ・課題4つ・ステークホルダー8名の懸念が並ぶ。設問は「最初に検討すべき改善案として最も適切なものはどれか」「MVPとして最初に着手するスコープとして最も適切なものはどれか」など。

ただし**これは第三者の予想問題であって公式の構造ではない**（サイト自身が明記）。上の「公式は非開示」で決着したとおり、**受験者に聞いても答えは出ない**。設計は 1ケース複数問（＝n=1 で1問も表現できる）で組むのが安全。

## サイトとのギャップ（2026-08-31 時点）

- **模試125問中ケース問題は1問だけ**。ケースは22問あるが全部 `pool:'both'`（レッスン所属）で、模試の「lesson 再利用は15問まで」の枠に阻まれて入らない
- ケース本文は中央値198字・設問文は中央値48字。本番の「長文読解」には短い
- 第1章の Sec1・2・3 が各2問と薄い

## HK の方針（2026-08-31）

**「まず知識、その上で長文」。** 知識が入っていない段階で長文を解いても読解の練習にならない。よってレッスンの短文問題は知識定着用として残し、長文化は仕上げ用として別に足す。全問長文化はしない。
