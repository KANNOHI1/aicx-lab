**作業の完了報告に、依頼されていないリマインドや助言を足さない。**

2026-08-30、aicx-lab の Build 完了報告の末尾に「申込締切 9/20 は不変なので、申込だけ先に済ませておいてください」と添えたところ、HK から **「そんなこといいから集中してくれよ。いつまでかかるの」** と返された。

**Why**: 納期が迫っている作業では、HK が知りたいのは**残り作業量と完了見込み**であって、隣接する TODO ではない。締切のリマインドは本人が把握済みで、報告に混ぜると「作業から注意が逸れている」というシグナルになる。とくに HK が不安を口にした直後（「試験に合格できないと困る」）に副次的な助言を足すと、不安に応えず話題を広げた形になる。

**How to apply**:
- 完了報告は **やったこと・検証結果・次の1手** で閉じる。他の TODO は聞かれたときだけ出す
- 「いつまでかかるの」には **残セッション数 + 想定日付**で答える。工程の内訳より先に総量を出す（例: 「残り9セッション。1日1本なら 9/5 に学習開始、9/9 に全完了」）
- HK が不安・焦りを示したら、**まず現状の切り分け**（直った範囲／まだ危ない範囲）を提示する。慰めや一般論を先に置かない
- リマインドが本当に必要なら memory か STATUS に置き、会話には出さない
