`spawn_task` で出したチップを HK が起動すると「fresh worktree で開始できる」と案内されるが、**実際には同じ作業ツリーの現ブランチ（main）へ直接コミットされることがある**。

2026-08-30 の aicx-lab で実際に起きた: 用語集の重複キー解消を切り出したチップが、こちらが Build F6b の編集中に同じ `index.html` を触り、`21485b9` を main へ commit した。今回は編集タイミングがずれて実害ゼロだったが、**同時に同じファイルを書いていれば片方の変更が消えていた**。

## How to apply

- **同じファイルを触る作業をチップに出したら、自分の編集と並行させない。** 出すなら「今の Build が終わってから」と明示するか、Build 完了後に出す
- チップを出した後で自分も同じファイルを編集する場合、**commit の直前に必ず `git log --oneline -3` と `git status -sb` で他者のコミットが入っていないか確認する**（ファイルを読み直してから書く。読んだ内容が古いまま書き戻すと相手の変更を消す）
- 予期しないコミットを見つけたら、消さずに**その上に自分の変更を乗せ直す**。`git log` で相手の意図を読んでから判断する
