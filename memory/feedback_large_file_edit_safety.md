数千行の単一ファイル（aicx-lab の `index.html` は約 4,000 行）を Bash/node から機械的に書き換えるとき、2 つの事故を実際に起こした。どちらもモデル非依存で、他プロジェクトでも同じ形で出る。

## 1. 行番号 splice は「開始・終端・その次」の3点を assert する

**やったこと**: `L.splice(start, end-start, ...新内容)` で HTML テンプレート文字列を差し替えた際、終端の行番号を 1 つずらしていた。その結果、隣の JS オブジェクトの `o:[` 行と正解の選択肢を上書きし、`SyntaxError: Unexpected string` を出した。

**なぜ危険か**: 入口（開始行）だけを assert すると、終端がずれても**エラーにならずに隣の要素を食う**。今回はファイルが JS を含んでいて構文エラーで即死したから気づけたが、Markdown や設定ファイルなら**壊れたまま静かに通る**。

**How to apply**: splice の前に最低 3 点を確認する。
- 開始行に期待する文字列があるか
- 終端行に期待する文字列があるか
- 終端の**次の行**が、置換対象の外側の要素であるか

`sed -n 'N,Mp'` の出力は 1-indexed、`Array` は 0-indexed。ここの取り違えが今回の直接原因なので、**assert に使う添字は必ず片方の流儀に統一して書く**。

## 2. 長い文字列の完全一致 replace は使わない

**やったこと**: 用語集の定義文（全角の `／`・`（）`・`→` を含む 200 字超）を `s.replace(old, new)` で置換しようとして、目視では同一に見えるのに `NOT FOUND` が繰り返し出た。

**How to apply**: 完全一致は**短くて特徴的なキー**にだけ使う（例: `'用語名':{y:` のようなオブジェクトのキー行）。本文の差し替えは
`findIndex` で行を特定して**配列要素ごと代入する**。

```js
const i = L.findIndex(x => x.includes("'用語名':{y:"));
if (i < 0) throw new Error('NOT FOUND');
L[i]   = "新しいキー行";
L[i+1] = "新しい定義行";
```

## 3. 書き込みはスクリプト末尾で 1 回だけ

複数の置換を 1 スクリプトにまとめ、**すべて成功してから最後に `writeFileSync`** する。途中で `throw` すればファイルは無傷なので、失敗しても手戻りがない。実際 F5a では最初の `rep()` が成功した状態で 2 つ目が `NOT FOUND` になったが、書き込み前だったのでファイルは元のままで、そのまま原因調査に移れた。

## 4. Bash heredoc で大きなファイルを書かない

既知（STATUS のハマりパターンにも記録済み）だが再掲。**約 7KB で無言に truncate される**。数 KB を超える内容は Write ツールで書く。今回も教材本文（約 10KB）と問題ブロック（約 18KB）は Write でスクラッチパッドに出してから node で読み込んで splice した。
