`const GLO = { 'A': {...}, ... , 'A': {...} }` のように同じキーが2回書かれていても、**JS は構文エラーを出さない**。後の定義が勝ち、前の定義は黙って捨てられる。

## なぜ厄介か

- **画面の見た目は正しい**（後の定義が表示されるので、たいてい新しい方＝正しい方が出る）
- そのため「表示は合っているから問題なし」と判断してしまう
- 実害は**前の定義を編集しても何も変わらない**こと。「直したはずなのに反映されない」で時間を溶かす
- 自作の検査スクリプトは「キーの存在」しか見ていないことが多く、**重複そのものを検査項目に入れていないと永久に見つからない**（aicx-lab の `tools/qcheck.js` は20項目あるが重複キー検査が無かった）

## How to apply

データを JS/JSON のオブジェクトで持つプロジェクトでは、検査スクリプトに1行足すだけで済む:

```js
const keys=[...src.matchAll(/^ '([^']+)':/gm)].map(m=>m[1]);
console.log('重複', keys.length - new Set(keys).size);
```

**「件数を数える」検査を書くときは、同時に「ユニーク件数と一致するか」も見る。** 総数だけ数えると重複を含んだまま「規定数ある」と誤判定する（実際 aicx-lab で用語数を134と報告したが、うち2件は重複で実効は132だった）。
